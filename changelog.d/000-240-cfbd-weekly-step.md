## 2026-11-03 (#000: 240-cfbd-weekly-step — the host's weekly CFBD read: `ncaa-cfbd-labels --year 2026` is the last step of weekly-fullseason (Sunday 06:00Z), metered, its failure receipted and paged as a sync-step failure that stops nothing after it (addendum 240 item 4(b)); ncaa-schedule unchanged)
- Addendum 240 item 4 (ARCHITECT 2026-11-03 17:40 ET), verbatim: "THE HOST'S CFBD READ (239 item 1(b)): no host chain calls CFBD and the key left the host's checkout at the cutover — so the pregame flag reaches the host only by a hand run after the migration. RULED: (a) for the 11-09 run's window the hand run is mine, by block, on the host via systemd-run with host.env, once CFBD_API_KEY is in host.env (the operator's hand step, NAME checked by my Thursday block, the value never printed); (b) a small ruled PR after #816 puts `ncaa-cfbd-labels --year 2026` on the host's weekly-fullseason chain (Sunday 06:00Z; metered, one read a week — the neutral flags of a week's games are known days ahead and seldom change), its failure a sync-step failure that stops nothing after it; the daily ncaa-schedule chain stays as it is." This PR builds item (b) only; item (a) is the architect's block.
- `deploy/hosting/chains.py`: `NCAA_CFBD_STEP = ["ncaa-cfbd-labels", "--year", "2026"]` (a named constant, as `NCAA_SHADOW_STEP`) and `CFBD_GO_ON` (the receipt's reason). `weekly-fullseason` gains `"steps": [NCAA_CFBD_STEP]` (the steps after the list's), `"go_on": ("ncaa-cfbd-labels",)` and `"go_on_why": CFBD_GO_ON`. The step is not added to `UNMETERED`, so it is METERED: under `SP_PARALLEL_MODE=designated` it runs only on a designated day, and the quota line counts it as a metered step. No meter or budget registry exists beyond `UNMETERED` and the H0-16(b) designated-days mode, so there is nothing else to register.
- `deploy/hosting/sp_run.py`: `resolve` returns the list's steps (`fullseason_resolve`, unchanged, which is also the path the cutover readout counts) followed by the chain's own `steps`. `run_steps` takes `go_on_why` (default `CHAIN_GO_ON`, ncaa-schedule's, unchanged): a failed go_on step's receipt `continued` is the chain's reason, and the printed line cites the reason's ruling. `main` passes the chain's `go_on_why`.
- Placement: LAST, after every `SP_FULLSEASON_LIST` sync, because both of the command's joins read our stored NCAA fixtures (the pregame flag joins by the exact name tier; a substring-tier label joins only where our stored score agrees), so that, when the host's list carries an `NCAA|2026` line, the week's full-season sync of them runs first, as teams run before matches. The host list's NCAA line is not verified by this PR (the list is generated on the host, hosting-h1.md step T9); first or last is the architect's to rule. Nothing after it reads the CFBD tables. The tradeoff: the read runs only when the list resolves (the setting is set, the file exists and it lists a competition; else `resolve` refuses before any step, as on 10-04, 10-11 and 10-18), the daily backup succeeds, and no earlier `sync-matches` fails (a failed one stops the chain before the read, as it stops every later step today); in every other case that week's read waits for a hand run or the next Sunday. Only the CFBD read (and sync-teams, addendum 207 item 4) goes on, not `continue_on_sync_failure` (wider than ruled).
- Unchanged: the ncaa-schedule chain (a test pins its definition word for word and its timer), the timer `sp-weekly-fullseason.timer` (`Sun *-*-* 06:00:00 UTC`), the cutover readout's count, the command itself.
