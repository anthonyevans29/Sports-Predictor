## 2026-10-17 (#575: void-redated — ARCHITECT addendum 106 item 4, addendum 107 item A2; #574, sibling #568)
- src/walters/redated.py (new): the rule in one place. `redated_label(recorded start, current utc_date)` returns "void: re-dated <old> → <new>" (UTC, `YYYY-MM-DD HH:MMZ`) when the two differ by more than `desk_policy.DESK_CLOCK_DRIFT` (1h). Exactly 1h is not void; a start with no clock, missing or unparseable, is not compared.
  - `closing_starts` reads `exports/closing_*.json` (never `host/`) into each match's closing rows (the run's start, the row's `utc_date`). An unreadable file is counted, never fatal.
  - `void_label`: a match is void when it has closing rows, none within the rule of its current start (the fresh closing on the new date is the graded row), and its latest is re-dated.
  - `label_rows` gives a results row the key `redated`, never `status` or `void` (the Cockpit's intake would read those as a called-off game and refund the fresh call).
- tools/cockpit.html (repo copy; the live Cockpit is the published artifact): `gradeLedger` compares a call's kickoff with its matched result's date (`redatedLabel`, `REDATED_DRIFT_MS` = 1h, the same text as the Python rule). More than 1h apart: the call gets `void_redated` (the label), status `void` and no result. The fresh call at the new start is graded as before; a date with no clock is not compared.
  - Out of every tally: `settledBets` / `agg` / the tables / equity / P&L read status `graded`; the CLV series, the n/30 counters (`gradedCount`) and `ledgerSummary` skip `void_redated` explicitly.
  - A parlay leg void as re-dated drops from its ticket, as a void leg does; the ticket settles on its other legs.
  - The ledger lists each void call with its label; the P&L block and the results-intake note count them (`Void: re-dated N`).
  - A void call is checked again at every intake: a result within the hour of its kickoff grades it and clears the label. A re-log of the position (`upsertCalls`) reopens it without the label. Calls graded before this change are not rewritten.
- Results exports: a row void by its closing rows keeps every field, gains `redated` and leaves every tally; `record.redated` counts them.
  - `export.export_results` (record games / hits / `vs_close`, `totals_pulse`; new `exports_dir`, default `exports`), `nfl_predict.export_nfl_results` (season and pre-live records, read from `out_dir`), `intl_production.export_results` (read from `out_dir`).

  - `export.results_tally` (new `exports_dir`): the MLB, Soccer (PL) and NFL sections leave the game out and name it on a `- Void: re-dated N` line, printed only when N > 0.
  - cli.py: `export-results`, `export-nfl-results` and `export-intl-results` print `void: re-dated N (kept in the file, out of every tally above)` and one line per row.
