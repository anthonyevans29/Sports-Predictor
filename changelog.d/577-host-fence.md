- src/walters/desk_policy.py: the host fence. Under role host, every soccer model row is PASS, `pass_kind` `host_fence`, reason "host: ratings keyed to the laptop's team ids (#410); the cutover replaces this database".
  - It is checked first, before S1 and every other rule, so it overrides any PLAY, LADDER or other PASS kind. It is in NO_CALL_KINDS: units 0, no order, no exec block, no value shadow, no shadow units, never a parlay leg.
  - `rating_source`, `model_p` and the prediction block are unchanged; the row's model numbers stay in the file for the compare. MLB, NFL, INTL and market-only rows (the venue engine) are untouched.
  - The role is the machine's `SP_EXPORTS_MIRROR_ROLE` (addendum 45 P1: host | laptop, no default), read by `machine_role()` from the machine's own host.env first (`SP_HOST_ENV`, default `/etc/sports-predictor/host.env`; only the host has one), then from the process environment (the units' EnvironmentFile, sp_run's `load_host_env`, config.py's `load_dotenv` of the checkout's `.env`). Only `host` fences (surrounding whitespace stripped, as `closing.mirror_role()` strips it); unset or any other value leaves the row as it is. It is not `SP_WRITER_OF_RECORD`, which reads laptop on both machines until the cutover flips it. This reading was built pending the architect's confirmation on #410.
  - Why host.env first (#410 review, P1): `closing.mirror_role()` reads the environment first, then host.env (`sp_common.setting`). A `closing-run` typed by hand on the host (the P8 rehearsal, under sudo) has no EnvironmentFile: it found `host` in host.env and signed its page `machine: host`, while its export step's environment had no role, or the laptop's role if the checkout's `.env` (a copy of the laptop's) carries it. That export ran the Desk unfenced, so a mis-keyed PLAY could reach the host pager and the window card. Reading host.env first fences that export, and any `cli.py` typed by hand on the host as `sp` or root (host.env is `root:sp 0640`; a user who cannot read it falls back to the environment). `closing.py` is not changed.
  - The switch is `HOST_FENCE_RULE`, which the cutover's PR turns off ("the fence lifts with the cutover"). `host_fence_rule_off()` is for comparison. `base_v11()` holds it off, so the frozen golden passes whatever the machine's role.
  - desk_meta gains `host_fence_rule` (the switch). The role itself is not written there: it would part every laptop/host desk file in the daily compare.
- The window card copies each row's Desk call (`window.canonical_models`), so on the host a fenced row reads PASS 0u on the card and on the pager's line.
