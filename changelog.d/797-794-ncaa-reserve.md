## 2026-11-02 (#797: 794-ncaa-reserve — ncaa-gate's reservation is written whole or not at all, the shape #784 got for nfl-v2-gate; addendum 221 item 1, a harness fix)
- **Ruling (verbatim, addendum 221 item 1):** "#794 — RULED: fix it, the same shape #784 got for nfl-v2-gate (the reservation written whole or not at all; a write failure leaves nothing and the run is not spent; a refusal records nothing), with its tests, in its own small PR that takes the slot #796 frees NOW — ahead of the two addendum-220 PRs still building, because it protects a model lane's one run (ncaa-elo-v2, 2026-11-09) and the leagues' and PL's records can wait an hour. It is a harness fix, not a criterion: the gate's bar, stream and reservation semantics are unchanged; `ncaa-gate --preflight`'s output stays byte-identical (a test pins it). Merged before 11-09 by my block; nothing on the roadmap moves. The `needs-ruling` label drops with this."
- **Fixed:** `src/walters/ncaa_v1r_gate.py` `reserve()`, which both declarations the gate serves share (ncaa-elo-v1r, ncaa-elo-v2). The body is serialised BEFORE the exclusive create, so a serialisation error creates nothing. After the create the whole body is written (a loop over `os.write`), fsynced and closed, and the directory is fsynced. On any failure the fd is closed, OUR file is removed, and the run refuses (exit 2: nothing scored, the read is not spent). If the removal fails too, the refusal says INSPECT THE FILE. A KeyboardInterrupt is cleaned up the same way and re-raised. A concurrent reserve still fails at the exclusive create, so it never removes anything. `_write_all` and `_fsync_dir` mirror nfl_v2_gate's (#784), so the NCAA gate imports no other sport's gate.
- **Unchanged:** the bar, the stream, the reservation's path, its contents (the bytes written on success equal the pre-fix `json.dump` + newline, pinned by a test against the old function), the exclusive create, when the reservation is written, and what refuses. `ncaa-gate --preflight`'s output is byte-identical for both ids (pinned against origin/main 212398ea's module on synthetic streams). Nothing on the roadmap moves.
- **Tests:** `tests/test_ncaa_reserve_794.py` (24): for both ids, the serialisation fault; the partial-write, write, fsync, close and directory-fsync faults, each followed by a whole reserve; the failed removal (INSPECT THE FILE); the KeyboardInterrupt; a short write completed by the loop; the directory fsynced after the file; a concurrent reservation never removed; the success bytes against the pre-fix function; `ncaa-gate --id <id>` whose reservation write fails exits 2 with nothing recorded, then succeeds; `--preflight` byte-identical. 18 of the 24 fail on the pre-fix module.
- **Docs:** docs/CLI.md's `ncaa-gate` row gets the clause on the reservation written whole or not at all.
- Review on #797 (round 1): a create that fails for any reason other than an existing file refuses (exit 2, nothing created); a removal is followed by an fsync of its directory, and a removal that cannot be made durable is said (the refusal then does not claim the read unspent); the newline is os.linesep, as the old text-mode write put it on disk.
- Addendum 222 item 1 (the round-two P2 rides this PR): the directory is fsynced after the cleanup whether our unlink removed the file or another process already had; a failed fsync is said and the read is not claimed unspent.
