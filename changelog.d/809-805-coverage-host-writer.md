- deploy/hosting/chains.py: `COVERAGE_STEP = ["coverage", "--json"]` is the LAST step of `intl-daily` (sp-intl-daily.timer, daily 07:20 UTC), after the four cups' sync-teams / sync-matches pairs, and on no other chain. Bare: its default `--out` is exports/coverage_<date>.json (the coverage day, today in US Eastern; relative to the working directory, which sp_run sets to the checkout for every step), the kind the exports mirror carries to host/latest/coverage.json. `coverage` joins `chains.UNMETERED` (it reads the DB mode=ro, the registry, the roadmap and exports/; no provider call), so designated-days mode never skips it. No new timer; no unit file changes.
- Exit handling is sp_run's, unchanged: no step follows it, so its failure blocks no sync step; the chain's exit carries it (the first failure's) and systemd's OnFailure pages. The exports mirror is pushed after it as after every step. A failed step before it that stops the chain (a cup's `sync-matches`, an intl step), or a failed daily backup before any step (sp_run.main then runs no step; the chain's exit is 1), leaves that day without a host coverage file; a failed `sync-teams` does not stop it (addendum 207 item 4).
