## 2026-11-04 (#831: 252-availability-record-schema — THE AVAILABILITY RECORD, the schema PR (ARCHITECT 2026-11-04 13:05 ET, addendum 252 items 1, 2, 6 and 7; lane availability-record): two append-only tables, their migration, the one writer, the one read path and the read-only `availability` command; no feed, no provider call, no model change)
- **The store:**
  - `availability_observations`, one row per fetch, and `availability_assertions`, one row per fact a payload asserted (`src/db/schema.py`).
  - Their vocabularies: three sources, Step B's five statuses, seven kinds.
  - SQLite triggers abort every UPDATE and DELETE on both tables. The insert guards refuse:
    - a source or kind outside the vocabulary;
    - an assertion on an observation that is not complete or partial, or that is not the newest observation (no backdating: nothing is appended to an older fetch);
    - a sport, or a `recorded_at`, other than the observation's;
    - a row whose id, or whose poll, is already stored (`INSERT OR REPLACE` cannot delete around the triggers).
  - `match_id` and `player_id` are plain integers with no foreign key, so `dedupe-matches` never re-points a record row.
  - `team_id` declares its reference to `teams.id`, unenforced, so `merge-teams` knows the column. A merge whose retired team holds record rows is refused by the update trigger, and the reason is receipted.
- **The migration:** `migrate_availability_record.py` is additive and idempotent. It creates the tables, `CREATE TRIGGER IF NOT EXISTS` for the six triggers, and the marker `availability_record_migration`. Its receipts are the triggers (created or kept, read before any table is created) read back from `sqlite_master` and the row counts. `drop_db` drops the marker.
- **The writer:** `src/availability/record.py` `write_observation(obs, assertions)` is the only writer. It writes one observation with its assertions in one transaction: `rows_asserted` is counted, and `recorded_at` is the observation's `fetched_at`. It refuses:
  - a missing DB file or an unmigrated store;
  - an unknown column name (law 1);
  - an endpoint carrying a secret: a secret env value, credentials in the URL (`user:password@`), or a credential-like parameter (`api_token`, `access_key`, `client_secret`, `apiKey`, `sig` and the like);
  - a payload path outside `logs/availability/<source>/<YYYY-MM-DD>/`.
  The error text is redacted: env secrets, URL userinfo, credential-like values in URL, header, dict and JSON forms, and bearer tokens. A poll already stored is counted "already". Unmapped players, teams and per-game matches are counted (law 4).
- **The read:** `derive` builds the derived interval (restated, closed "asserted differently", closed "slot asserted to someone else", opened). `as_of` is the derivation over the assertions at or before the instant under the recorded or the source clock, keeping the open intervals. `history` lists every assertion in time order with its interval's end. Facts and slots are keyed on the source's own identifiers, so a mapping that lands between fetches never splits a fact. Facts are labelled BACKFILLED (nflverse cadence 24 h, proposed) only while every row of the interval is backfilled; a fresh restatement prints `live-era from`. POST HOC as ruled. `--history` lines carry each row's own labels. The nflverse attribution line prints with nflverse facts.
- **Codex on #831, round 1 (three repairs):** a per-game fact on a league-wide file is labelled POST HOC against the kickoff `matches` stores for its match, as stored at read time (the current kickoff, not as of the instant; a stored fetch-time kickoff comes first), and reads `kickoff unknown` when no kickoff is stored anywhere; the `--match-id`/`--team` filters and the printed ids take each of our ids from the latest member of the interval that carries one, so a fact restated after its team or match maps, or restated unmapped after it mapped, is found by our id; per-game facts are keyed on the source's own game id (`attrs.source_match_id`, required from `nhl_api_landing`), so a restatement after the match maps is the same fact and its slot closes.
- **The command:** `python cli.py availability --sport S --as-of INSTANT [--clock recorded|source] [--match-id N | --team T] [--kind K] [--history] [--db PATH]`. It is read-only: mode=ro, or for `--db` a copy behind the standing fence. Exit 2 on a refusal.

- **Addendum 252, verbatim (items 1, 2, 6, 7):**

> 1. THE MODEL, bitemporal and append-only. Two tables, both created by one migration, both written by ingest commands only, both read mode=ro by everything else:
>    (a) `availability_observations` — one row per fetch: sport; source (a fixed vocabulary, item 3); endpoint (the URL or file name, no secrets); the match_id where the fetch is per game (NULL for a league-wide file), the stored kickoff then; poll_label where polled on a schedule (the probe's T-120 … T-0); scheduled_at; fetched_at (OUR clock, UTC); http_status; payload_sha256; payload_path (the raw answer kept on disk under logs/availability/<source>/<date>/, never under data/, never mirrored); status: complete | partial | empty | failed | missed (Step B's five, the same meanings); late; error (redacted); rows_asserted. NOTHING UPDATES OR DELETES A ROW. A fetch that raised is a row; a poll whose time passed with no call is a row.
>    (b) `availability_assertions` — one row per fact a payload asserted, keyed to its observation: observation_id; sport; kind (a fixed vocabulary: depth_rank | projected_starter | confirmed_starter | eventual_starter | inactive | injury_status | plays_for); player_id (ours, NULL with the source's id beside it when unmapped: source_player_id, player_name verbatim); team_id (ours; NULL + source_team verbatim when unmapped); match_id (NULL for a team-level fact); attrs JSON (pos_abb, pos_slot, pos_rank, status text, the side); source_stamp (THE SOURCE'S OWN TIME for the fact: nflverse's `dt`; NULL where the source gives none — the NHL landing gives none); recorded_at (= the observation's fetched_at, denormalised for the as-of query). No valid_to column and no update: an interval is DERIVED — a fact holds from its observation to the next observation of the same source that asserts the same (kind, player, team[, match]) differently, or that asserts the slot to someone else. "As of T" is one query: the newest observation per source with the chosen clock <= T, and its assertions. That is StackState's time travel in two tables and a WHERE clause.
>    THE TWO CLOCKS, ruled now so no term argues it later: `recorded_at` is OUR knowledge; `source_stamp` is the source's claim. A live-era record, a forward confirmation and a closing-time input use `recorded_at` only (what we had on our disk before the cut-off). A backfilled row (recorded_at later than source_stamp by more than the feed's cadence: nflverse's season file reaches back to its first load, so our first fetch records weeks of history at once) is usable ONLY in a backtest labelled "source-stamped" in its run record and its gate text, never in the live-era record; a term that wants it declares that in its bar. Both clocks are kept on every row so either reading can be audited.
>    Mapping (law 4): a player or team the source names that we cannot map stays NULL with the source's text beside it; mapping is by the existing tables' source ids (players.gsis_id / espn_id where we hold them, nhl player ids as nhl_goalies stores them) and never by name alone; an unmapped row is counted on the ingest's console and in a receipt, never dropped and never guessed.
>
> 2. THE QUERY SURFACE (read-only cli, one command): `availability --sport S --as-of INSTANT [--clock recorded|source] [--match-id N | --team T] [--kind K]` prints the facts in force at the instant under the chosen clock, each with both stamps and its observation; `--history` prints every assertion for the key in time order so a flip shows. The same function is the one a model term, the bulletin's teams section and the Cockpit will read; there is no second path.
