- **The class closed:** `tests/test_privacy_patterns_linear.py` reads the module, not a list of names. It takes every `re.Pattern` the module holds, plus every pattern the module's source passes to `re.*` inside a function. A pattern built at call time from anything but a literal fails the test until it is named at module level. So does `re`, or one of its pattern functions, held under another name (an alias, `getattr`, `lru_cache(re.compile)`), since a call through it could not be read. Two calls on one line are read as two. Each pattern reads 40 shapes through `finditer` at 2,000, 10,000 and 50,000 characters, under one bound of 20 microseconds a character. Each pattern reads in a child process, each read under a deadline (ten times its bound and a second), so an exponential pattern fails naming its shape instead of hanging the run. Further tests prove the bound is not vacuous (main's `CSV_RUN` and `FRACTION` before this PR read over it) and the deadline fires (`(?:a|a?)+b` fails at 2,000 letters).
- **The Issue's "34 shapes" was a miscount:** #979's scan held 33. The test runs those 33, three found while building (a field and tabs, a field and space-tab pairs, and upper case) and four the money-path review found (a field, or a field and a comma, and a run of spaces; a digit, an underscore or not, and a run of letters). Each of the four catches a mutant that matches the same strings and is quadratic again.
