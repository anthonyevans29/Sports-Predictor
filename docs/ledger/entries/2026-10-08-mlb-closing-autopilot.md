**2026-10-08 — RULED + BUILT (ARCHITECT, addendum 13 item 3, Q2): the MLB closing-run autopilot (laptop only).**
- **Ruling (verbatim):** "Laptop only: the host cannot reach the MLB feed."
  - "A1. mlb-closing-run is one command. It runs the ten mlb-preslate steps as chains.py lists them (chains.py stays the one place commands live), with the export carrying the Desk's call, then prints one summary block per game whose first pitch is within 90 minutes and pushes the exports mirror as role laptop, label closing. The date the steps take is the first pitch's date in America/New_York, the feed's own date, never the UTC date."
  - "A2. It runs under the chain lock, stops at the first failed step, exports and pushes nothing after a failure, and appends one receipt line either way: the first-pitch time, each step's exit code and seconds, the export file, the Desk rows, the push."
  - "A3. Before the first step a .backup dated today must exist in the operator's backup folder. If none does, it takes one through the .backup API and checks that it opens. Nothing under data/ is copied any other way."
  - "A4. It never produces a call for a started game. The Desk's started rule already makes that row PASS; the command also refuses to start when every game in its window has started."
  - "A5. mlb-closing-watch is the tick, and it uses no network to decide. From the stored schedule it takes the MLB games not started whose first pitch is 5 to 65 minutes away. If one of them has no successful closing receipt for its first-pitch time, it starts mlb-closing-run once. Otherwise it exits 0 and prints nothing."
  - "A6. Before starting the run the watch checks that the MLB feed answers. If it does not, it runs nothing, posts a macOS notification 'MLB feed unreachable: VPN on, Tailscale off', records the miss, and tries again on the next tick while the window is open. A failed run is retried the same way, at most three attempts for one first-pitch time."
  - "A7. After a successful run it posts one notification per game: first pitch, the call, the pick, units and exec edge. A PLAY whose exec edge is under 4.0pp carries 'paste to the architect before placing', and the summary block prints the same hold on the order line. The hold is the operator hold of 2026-10-07 and lives in one small table so lifting it is a one-line PR. The autopilot places nothing and never opens Kalshi's trading API."
  - "A8. scripts/setup_mlb_closing_watch.sh installs and removes a LaunchAgent that runs the watch every 5 minutes, on the pattern of setup_clv_capture.sh, logs under logs/. The operator installs it. Nothing installs itself, and --uninstall is the off switch."
  - "A9. --dry-run on both commands prints what would run and touches nothing: no step, no backup, no receipt, no push, no notification."
- **A1, the export:** `CHAINS["mlb-closing"]` in `chains.py`, derived from `mlb-preslate`. Steps 1–9 are its own; the export adds `--date {today} --desk`, so it carries the Desk's call. The run sets `{today}` to the first pitch's NY date. `--date` is needed because the export's default slate is the UTC date, which drops a late ET game after 20:00 ET. `sp_run.py` refuses the chain: it is laptop only.
- **A3, the folder:** `SP_BACKUP_DIR` when set, else `~/backups`, the folder of the documented backup line. "Dated today" means the NY date, and any `sports_<date>*.db` counts. Ruled as built (addendum 16 item 2, below).
- **Receipts:** `logs/receipts.jsonl`. `kind: mlb_closing` is one line per run, success or failure. `kind: mlb_closing_miss` is a feed miss. The watch reads both: whether there was a success for a first-pitch time, and how many attempts (at most 3).
- **A7, the hold:** `CLOSING_HOLDS` in `deploy/hosting/mlb_closing.py`, one row. An unknown exec edge is held (law 4).
- **Operator:** install with `bash scripts/setup_mlb_closing_watch.sh`; the operator section is in docs/CLI.md.
