**2026-10-09 — RULED + BUILT (ARCHITECT, addendum 28 item 2): #390 items 6 and 7. (6) A game is finished with at the start time it was covered at, and at no other. (7) The unpaged called-off games are bounded to the schedule's window.** Daily-class: no model, gate, threshold or Desk rule changes. The PR references #390 and does not close it.
- **Ruling, item 6 (verbatim):** "Item 6, RULED. I ran it on the preview: a game a successful run covered, whose stored start then moves, forms no group again. The same holds for a game paged as postponed and later stored as scheduled at a new start. covered_ids is a set of match ids, so finished with lasts for good. Addendum 26 said "at a start time", and this is the rule: "A game is finished with at the start time it was covered at, and at no other. When its stored start is no longer the start a receipt covered it at, that receipt says nothing about it: it is a new start time for the watch, whether the receipt was a success or the last of three attempts. A game paged as cancelled or postponed and later stored as scheduled at another start is such a game." Reading 6 stands for the page; this is what follows the page. The case is the makeup of a rained-out MLB game: it keeps its id, and today it would get no closing and no miss. That is silence where a closing did not happen. Build: each receipt already records the start it covered a game at; compare it with the stored start. Two tests that fail on #392's head: a game paged and then moved; a game paged as postponed and then rescheduled. Each new start forms its group and runs."
- **Ruling, item 7 (verbatim):** "Item 7, a nit, in the same PR. unpaged_called_off reads every receipt the family has. A game recorded as called off at a start time that ended with one or two failed attempts is added to the watch's games on every tick from then on. It can never be due, since its start has passed, but closing-watch --dry-run lists it for good and the list only grows. Bound it to the window schedule() reads."
- **Not built (verbatim, not ruled):** "A note beside item 5, not ruled. On a retry, a called-off game that is still a game of its start time is named in the schedule read again (resolve_steps names every cover). If the provider has dropped it from that date between the attempts, the read fails and the whole start time loses its page. It is reading (a)'s edge reached another way. I rule on both with a real case in hand."
- **Item 6 built:** `deploy/hosting/closing.py`:
  - `covered_ids` collects (match id, covered start) pairs from the finishing receipts. These are the covers of a successful attempt, and the covers of the last attempt once a start time has had three. Moved games are still subtracted per receipt.
  - It returns a match id only while the game's stored start equals the start a finishing receipt covered it at.
  - `stored_starts` (new) re-reads the stored starts by match id, read-only, in any window and with any status, the same read `start_moved` makes.
  - Readings:
    - The start a receipt covered a game at is the cover's own `start` (`covers[].start`, written by `_covers_rec` since #385). It is the game's start, not the run's target start. For a called-off game it equals the `covered_start` in `called_off`.
    - A cover with no readable start, or a game no longer stored, is finished with nowhere (law 4: the receipt says nothing about it).
    - The comparison is in `covered_ids` itself, so every caller (`due`, and through it `watch` and the dry run) reads it.
    - `unpaged_called_off` is not changed for item 6. A rescheduled called-off game inside the window is in `schedule()` at its new start and is not added back. Outside the window, a retry that covers it at the old start finds it moved in `leave_moved` (`start_moved`, after `called_off` re-reads it as SCHEDULED).
- **Item 7 built:** `deploy/hosting/closing.py`:
  - `unpaged_called_off(fam, now, hours=SCHEDULE_HOURS)` keeps only the called-off games whose covered start is in [now - 6h, now + 6h).
  - `schedule_window` (new) is the window `schedule()` reads, `utc_date >= lo AND utc_date < hi`, and both functions read it.
  - `with_called_off(fam, games, now)` passes the same `now` from its three callers: `plan` (now), `_under_lock` (held, the moment the run holds the lock) and `due` (the tick).
- **Finding, not built (for a ruling):** `closing_state`, and so the 380.4 superseded check, is keyed on the start time. If a moved game's new start is exactly a start time that has already had a success or three attempts, its group forms and is due. The run is then receipted as superseded on every tick until T-5, posting nothing: still no closing and no miss for that game. This was found while reading `_under_lock` for item 6 and is not exercised by the ruling's two tests.
