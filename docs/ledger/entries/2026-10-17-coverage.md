- **Built (#576):** deploy/hosting/coverage_map.py behind `python cli.py coverage`.
  - The DB is opened mode=ro; no row or export is written. On a WAL file (the real DB's mode) SQLite itself leaves its -wal/-shm sidecars beside the file, as for every `ro_connect` reader (the -wal empty, the file's bytes unchanged; a test holds both).
  - It reads the DB, docs/roadmap.json, docs/registry/experiments.json, the watch's schedule inputs (chains.py, closing.py) and the watch's receipt log (`SP_RECEIPTS` or logs/receipts.jsonl), plus the settings `closing._family_refusal` and `sp_run.active_from` read (SP_SKIP_FAMILIES, a chain's `active_from_env` such as SP_NHL_ACTIVE_FROM), nothing else. The second is a setting of the first's class, read where sp_run reads it; named for the architect, in case item 1's "nothing else" is read strictly.
  - **A run done (item 1):** a start time of the day with a closing run in the log prints `done (run <run_id>, <exit>)`, the ruling's words.
    - The run id, exit and covers are the receipt's own keys, as `closing.run` writes its receipt line. The runs are `closing._attempts`: a refusal or a superseded run is no run (380.4).
    - Several runs for one start time: the latest success where there is one (`closing.closing_state`: any exit 0), so a later failed run (an operator's re-run of a closed start time; only a watch run is superseded) never hides it; else the latest run, the log being append-only.
    - A done start time is never printed as due. Where the watch still forms a group at it, the done line says what the watch does with it, as the watch decides. Inside T-5, `closing.due` holds it as inside and `closing.watch` records a miss with no attempt: `(inside T-5: no further attempt, the watch records a miss)`. Ahead or due, `closing._under_lock` supersedes a watch run for a start time with a success or three attempts (`closing_state`): `(a successful closing: the watch runs it no more)` or `(3 attempts: …)`. Otherwise `(attempt N of 3: the watch tries again)`. The line then names the group's games the run's covers do not hold (`; not in its covers: …`), a game stored at the start time after the run.
    - Then the export file the run landed in (C7: "the export file each lands in"), the receipt's own `closing_file`: `; closing file exports/<name>`. Where closing.py's write failed after the page went out (`closing_file_failed`, or an error in `closing_file`), the run is exit 0, `closing_state` holds a success and the start time is never run again, so nothing else on the line would show it: `; closing file NOT written (exports/<name>): receipted and notified, not run again`, closing.py's own words. Only the receipt is read, nothing under exports/; no capitals gap is claimed for it (C7's gaps are prediction rows).
    - A log that cannot be read keeps `closing: not shown (…)`.
  - **The groups still to run** are `closing.groups()` on `closing.due()`'s own inputs: the stored games plus the unpaged called-off ones (`with_called_off`), less the games a closing has finished with (`covered_ids`). Each is ahead, due now (T-35 to T-5) or inside T-5 (a miss: no attempt, no file), by `due()`'s own thresholds. The run time and the file name are closing.py's own (`RUN_LEAD_MIN`, `closing_name`).
  - A family this machine refuses (`closing._family_refusal`: SP_SKIP_FAMILIES, MLB on the host) prints the refusal in place of its groups and claims no gap.
  - `coverage()` returns the map as data for the morning page, each game's computed_at per model included.
- **The status, in the ruled order (item 2), read from data and code; coverage_map.py names no competition (a test holds it):**
  - **LIVE:** a closing family covers it (`closing.FAMILIES[fam]['comps']`, the families of chains.CLOSING_FAMILIES) and the model its closing chain's predict step writes with resolves.
    - "A live model in the registry": docs/registry/experiments.json holds no live model (MLB v2, soccer v22 and nfl_elo_v1 predate it). So the model of record is read where the predict path reads it.
    - `predict --sport S` uses the one production row of S's model family in the DB's model_versions (`training.MODEL_FAMILIES`; generate_predictions → `_resolve_model_version` → `_current_production_version`). Printed `LIVE (closing family SOCCER; production soccer_elo_poisson v22)`.
    - `predict-nfl` writes `nfl_predict.MODEL_VERSION` on every row and has no model_versions row. Printed `LIVE (closing family NFL; predict-nfl writes nfl_predict.MODEL_VERSION nfl_elo_v1)`.
    - No production row, or more than one, or a model_versions table that cannot be read: not LIVE. The reason stays on the line and the derivation goes on.
  - **SHADOW:** a roadmap lane names it in `competitions` (never its prose), and either:
    - (a) the lane is confirming and its registry entry is confirming: UNL (intl-elo-v2) and PD (soccer-expansion-v1); or
    - (b) in any other state, a chain in chains.py runs a shadow export for it: a step whose command is one of the four cli commands whose rows carry engine model_shadow (export-nhl-predictions, export-unl-predictions, export-ncaa-predictions, export-soccer-expansion-shadow), in a chain whose steps name the competition. An operator-only chain is no schedule.
    - NHL qualifies by (b). Its lane is "to declare", not confirming or declared, but the ruling names NHL v7 as its example, and nhl-daily runs export-nhl-predictions (nhl_elo_v7_xg_margin_no_na) every day. A test shows it, and shows NHL MARKET-ONLY alone once that step is gone.
    - A chain outside its season gate on the day runs nothing: `sp_run.active_from` (the chain's `active_from_env` setting, else chains.py's date) is the gate sp_run skips the chain by, and a malformed setting fails it. So it is no schedule that day and the line names the gate (`no shadow export scheduled for NHL (chains.py: nhl-daily inactive until <date> [<source>])`). Tests: the setting unset, the coverage day itself (the shadow stands), the day after and malformed (no shadow), and `--date 2026-09-25`, before chains.py's 2026-09-29.
    - NCAA's lane is declared but no chain runs a college shadow (CLAUDE.md: "No college shadow ... until then"), so NCAA is not SHADOW. A test shows it would be reported if a chain ran export-ncaa-predictions.
    - PD's shadow export (export-soccer-expansion-shadow) is run by no chain; PD qualifies by (a).
    - The tag is the vN token of the shadow's id as the code names it: the registry id in (a), the shadow module's model id in (b). That gives v7, v2 and v1, or the full id where there is no vN token (ncaa_elo_v1r).
  - **MARKET-ONLY:** the code's own sets, imported, never copied:
    - `desk_policy.SHADOW_VENUE_COMPS`, the set `cli._refuse_shadow_league` refuses;
    - `chains.EXPANSION_CODES` and `chains.KALSHI_CAPTURE_ONLY`;
    - `export._MARKET_ONLY_REASON`, the market-only fixtures file's NHL, NCAA and UNL;
    - `cup_coeff.EXAM_COMPS`, the cup track's competitions (CL, EFL, UEL, and EL as the adapter's alias). No constant in the code names the cups as market-only; EXAM_COMPS is the set whose gate keeps them so. The ruled list (NHL, NCAA, CL, EFL, UEL, UNL and the five expansion leagues) is their union, EL aside.
    - Both SHADOW and MARKET-ONLY print `MARKET-ONLY · shadow v7` (NHL), `· shadow v2` (UNL) and `· shadow v1` (PD).
  - **UNKNOWN** only when none applies, with every reason: no closing family or no live model; no lane names it, or none qualifies (a registry id the registry does not hold, a lane and an entry that disagree); in none of the market-only sets. A roadmap or registry that cannot be read judges no shadow, and the line says so.
  - On the tracked files and code today: MLB, PL and NFL LIVE (given their production rows); NHL, UNL and PD `MARKET-ONLY · shadow v7/v2/v1`; NCAA, CL, EFL, UEL, SA, BL1, FL1 and ELC MARKET-ONLY; EL1, EL2, FAC, the WCQ groups and friendlies UNKNOWN.
- **The gaps:**
  - A gap is a LIVE competition with a game that has no prediction row.
  - No gap is claimed for SHADOW and MARKET-ONLY competitions (no chain runs a predict step for them: the cli writes rows only through `predict` and `predict-nfl`; a shadow prices in its own export). The spec's example is a live league.
  - The hint after the dash is derived from chains.py and is printed only when no game has a row: the chain whose model step is the closing chain's, word for word, not a closing or a freshen chain.
  - UNKNOWN competitions are named once, in capitals, with no gap judged.
- **Not read:** the host watch's own family list (`--family NFL --family SOCCER` in sp-closing-watch.service) is a unit argument, not a setting. SP_SKIP_FAMILIES=MLB covers the host's MLB case.
