**2026-10-17 — RULED (ARCHITECT 2026-10-17 09:30 ET, addendum 107 item C7): `python cli.py coverage` prints the day's coverage, one line per competition, then the gaps in capitals; read-only (#576).**
- **The spec (verbatim):** "`python cli.py coverage [--date YYYY-MM-DD]` (default today, ET): for each competition with games that day — count of games; whether a model is LIVE, MARKET-ONLY or SHADOW for it (from the registry/roadmap, not hard-coded strings); which stored prediction rows exist for those games (model, computed_at) and which games have none; the closing groups the watch will run (T-35 times, match ids) from the closing-watch schedule; and the export file each lands in (exports/<name> by the existing naming). One line per competition, then the gaps in capitals ("PL: 4 GAMES, 0 PREDICTION ROWS — soccer-prematch has not run"). Reads the DB and the schedule only; writes nothing; no provider call. It becomes the first step of every morning block and the source of the morning page's coverage map. Tests on the throwaway DB: a day with rows, a day with a gap, a market-only sport."
- **Built (#576):** deploy/hosting/coverage_map.py behind `python cli.py coverage`.
  - The DB is opened mode=ro; no row or export is written. On a WAL file (the real DB's mode) SQLite itself leaves its -wal/-shm sidecars beside the file, as for every `ro_connect` reader (the -wal empty, the file's bytes unchanged; a test holds both).
  - The closing groups are `closing.groups()` on `closing.due()`'s own inputs: the stored games plus the unpaged called-off ones (`with_called_off`), less the games a closing has finished with (`covered_ids`, from the watch's receipts, read-only). Without the receipts, a game a closing had finished with stayed a candidate, and after a first pitch the later start times re-anchored on it, naming files the watch never writes (review of #576). Each group is ahead, due now (T-35 to T-5) or inside T-5 (a miss: no attempt, no file), by `due()`'s own thresholds. The run time and the file name are closing.py's own (`RUN_LEAD_MIN`, `closing_name`).
  - A family this machine refuses (`closing._family_refusal`: SP_SKIP_FAMILIES, MLB on the host) prints the refusal in place of its groups and claims no gap.
  - A game's day is its US Eastern date, as the closing watch dates a first pitch.
  - `coverage()` returns the map as data for the morning page, each game's computed_at per model included. The line prints a model's computed_at as a range when its rows differ, so an old row is never hidden behind a fresh one.
- **Where the status comes from (read from the files, law 1):**
  - Neither the roadmap nor the registry names a competition code. A roadmap lane is matched to a competition only where its id is the code: unl, pd, ncaa, nhl. On the files today that gives UNL and PD SHADOW (confirming, with intl-elo-v2 and soccer-expansion-v1 confirming), NCAA MARKET-ONLY (declared, ncaa-elo-v2 declared) and NHL MARKET-ONLY (to declare).
  - The three live models predate both files and no lane names them. LIVE is read from the closing families (`closing.FAMILIES[fam]['comps']`, the families of chains.CLOSING_FAMILIES; C1: "A closing run exists for every family whose calls come from a live model"): MLB, NFL and PL. A lane named for a competition gives LIVE in state live, SHADOW in state confirming, its registry entry (if the lane names one) agreeing.
  - The lanes "leagues" (SA, BL1, FL1, ELC) and "cups" (CL, EFL Cup, UEL) name their competitions in prose only. Those competitions, and any other no lane or family names (EL1, EL2, the internationals), print UNKNOWN with the reason (law 4). A competitions list on each lane would derive them; that is a roadmap change, which needs its own ruling.
  - A lane and its registry entry that disagree, or a registry id the registry does not hold, print UNKNOWN as well.
- **The gaps:**
  - A gap is a LIVE competition with a game that has no prediction row.
  - No gap is claimed for SHADOW and MARKET-ONLY competitions (no chain runs a predict step for them: the cli writes rows only through `predict` and `predict-nfl`, and the web UI's per-match refresh and admin predict job reach the same training.generate_predictions; a shadow prices in its own export). The spec's example is a live league.
  - The hint after the dash is derived from chains.py and is printed only when no game has a row: the chain whose model step is the closing chain's, word for word, not a closing or a freshen chain.
  - UNKNOWN competitions are named once, in capitals, with no gap judged.
- **Open (needs-ruling):** the spec says "Reads the DB and the schedule only". The groups read the watch's receipts, read-only, because the groups the watch will run depend on them. Whether "the schedule" includes the receipts log is the architect's to rule; without them the groups must be marked as possibly re-anchored, never printed as runs.
- **Not read:** the host watch's own family list (`--family NFL --family SOCCER` in sp-closing-watch.service) is a unit argument, not a setting. SP_SKIP_FAMILIES=MLB covers the host's MLB case.
