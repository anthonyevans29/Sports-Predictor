- **The spec (verbatim):** "`python cli.py coverage [--date YYYY-MM-DD]` (default today, ET): for each competition with games that day — count of games; whether a model is LIVE, MARKET-ONLY or SHADOW for it (from the registry/roadmap, not hard-coded strings); which stored prediction rows exist for those games (model, computed_at) and which games have none; the closing groups the watch will run (T-35 times, match ids) from the closing-watch schedule; and the export file each lands in (exports/<name> by the existing naming). One line per competition, then the gaps in capitals ("PL: 4 GAMES, 0 PREDICTION ROWS — soccer-prematch has not run"). Reads the DB and the schedule only; writes nothing; no provider call. It becomes the first step of every morning block and the source of the morning page's coverage map. Tests on the throwaway DB: a day with rows, a day with a gap, a market-only sport."
- **Built (#576):** deploy/hosting/coverage_map.py behind `python cli.py coverage`.
  - The DB is opened mode=ro. The closing groups, the run time and the file name are closing.py's own (`groups`, `RUN_LEAD_MIN`, `closing_name`).
  - A game's day is its US Eastern date, as the closing watch dates a first pitch.
  - `coverage()` returns the map as data for the morning page.
- **Where the status comes from (read from the files, law 1):**
  - Neither the roadmap nor the registry names a competition code. A roadmap lane is matched to a competition only where its id is the code: unl, pd, ncaa, nhl. On the files today that gives UNL and PD SHADOW (confirming, with intl-elo-v2 and soccer-expansion-v1 confirming), NCAA MARKET-ONLY (declared, ncaa-elo-v2 declared) and NHL MARKET-ONLY (to declare).
  - The three live models predate both files and no lane names them. LIVE is read from the closing families (chains.CLOSING_FAMILIES; C1: "A closing run exists for every family whose calls come from a live model"): MLB, NFL and PL.
  - The lanes "leagues" (SA, BL1, FL1, ELC) and "cups" (CL, EFL Cup, UEL) name their competitions in prose only. Those competitions, and any other no lane or family names (EL1, EL2, the internationals), print UNKNOWN with the reason (law 4). A competitions list on each lane would derive them; that is a roadmap change, which needs its own ruling.
  - A lane and its registry entry that disagree, or a registry id the registry does not hold, print UNKNOWN as well.
- **The gaps:**
  - A gap is a LIVE competition with a game that has no prediction row.
  - SHADOW and MARKET-ONLY competitions write no prediction rows (only `predict` and `predict-nfl` write them; a shadow prices in its own export), so no gap is claimed for them. The spec's example is a live league.
  - The hint after the dash is derived from chains.py and is printed only when no game has a row: the chain whose model step is the closing chain's, word for word, not a closing or a freshen chain.
  - UNKNOWN competitions are named once, in capitals, with no gap judged.
- **Not read:** the watch's receipts (the spec: the DB and the schedule only). A start time already closed still shows until its games start. SP_SKIP_FAMILIES is not read either, so the host's refusal of MLB runs is not shown.
