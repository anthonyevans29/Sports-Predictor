- **Ruling (ARCHITECT 2026-10-17 10:40 ET, addendum 112 item 1), verbatim:** "#524 — migrate_*.py with no DB file at the configured path creates an empty WAL-mode database. RULED: every migration refuses when the file is absent ("no database at <path>; a migration never creates one — law 5"), exit 1, nothing written; one shared guard in the migrations' common helper; a test. This is the 2026-10-06 incident's shape (an empty DB under data/) and it is still open: do it first."
- **Law changed: law 5** ("The database never travels and is never touched casually"). A migration never creates a database: with no file at the configured path it refuses before its first connection. This is the BACKLOG entry #524's "Law changed" section points to.
- **The finding (#524):** the `migrate_*.py` scripts reach the DB through the app's engine (`get_engine()`). Its connect hooks make the missing directory (`do_connect`) and set WAL on a new, empty file (`connect`). The script then refuses ("matches table doesn't exist") and leaves the empty file and its directory behind. Reproduced on origin/main 5e520f9 with migrate_phase7.py: `sports.db`, `-wal` and `-shm` created under a directory that did not exist.
- **Built (#579):**
  - `src/db/migrate_guard.py`, `refuse_missing_db(engine)`. No migrations helper existed (every script imports only `get_engine` from src/db/database.py, the app's engine module), so the guard is a small module of its own.
  - It reads the engine's own URL: the file the SQLite driver would open, `DATABASE_URL` or config's default, a relative path read against the working directory. An in-memory SQLite URL is refused. A non-SQLite URL passes: there is no file, and connecting to a server never creates its database.
  - All 21 top-level `migrate_*.py` call it first in `main()`. migrate_kalshi_settled_markets.py's own #521 check moves onto it, with the ruled words.
  - One test runs every `migrate_*.py`, found by glob, against a missing file in a missing directory: exit 1, the ruled line, nothing created.
- **Elsewhere:** no other migration runs through `get_engine()`. `deploy/hosting/sp_migrate.py` is the host move (`.backup` pack, verify, install over sqlite3), not a schema migration. `sp_deploy.py --run-migrations` runs the top-level scripts, so it gets the guard through them.
- **Not changed:** `database.py`'s `do_connect` mkdir (the app's first run relies on it; out of scope per #524).
