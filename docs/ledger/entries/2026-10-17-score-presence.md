- **Built:**
  - `src/adapters/api_sports_status.py`, shared by both api-sports game adapters (american football: NFL and NCAA; hockey: NHL). It reads the provider's short as sent, before any `NS` default. ABSENT means the status block missing, null or empty, or its short null or empty. ABSENT with both totals is FINISHED. ABSENT with a total missing is SCHEDULED (no score, not FINISHED). A stated short keeps its mapping (a stated `NS` with scores stays SCHEDULED), and a code the map lacks is SCHEDULED whatever the scores.

- **Read as built:**
  - **The literal text "None" is a stated status.** Neither adapter ever wrote it for an absent status: a null status becomes `{}` before it is read, and a non-dict block is read as text only when it is not empty. So "None" reaches the parse only as text the provider sent itself. The absent class the rule was written for had "NO status block upstream (short=None, full totals present)" (2026-09-05). A stated "None" therefore keeps its mapping, which is none, so it is SCHEDULED (law 4). Before this PR, that text with both scores read FINISHED. The dry run lists such rows apart, so a provider that does send the text is seen before anything is written. Hockey's `status_raw` now keeps that text verbatim (before, it was dropped); a status not stated stays null.
  - **The fixtures are written, not kept.** No kept american-football or hockey answer exists in tests/fixtures. The rows are in the provider's shape as the adapters read it, and the folder's README says so. If kept answers are wanted, the operator captures a season's `/games` and Code trims rows in, as with kalshi_history and lineups_history.
  - **The dry run's vehicle.** sync-matches is what writes. For each listed game, `_apply_match_updates` sets the stored status and also writes the kickoff, matchday, stage and every present score. So the dry run makes the season read's one `/games` call (no date) and parses it with the adapter's own `_parse_games`. It keeps each game's status as sent and compares by provider id. The fix changes exactly two classes of listed game, both with their two totals: no status stated (now FINISHED) and the text "None" (now SCHEDULED). It prints, per competition-season:
    - the rule's changes, each with its match id, provider id, kickoff, stage, and stored → new status;
    - rows already as the fixed parse reads, and listed rows not stored;
    - every stored SCHEDULED row carrying both scores that the rule leaves, with why (a stated status, a score missing, not in the listing). These reconcile with addendum 81's 120 and 16.
    - what the same whole-season sync would write besides the rule: other statuses, kickoffs, and scores (values never printed);
    - a last line `SCORE-PRESENCE-DRY-RUN {counts}`.
