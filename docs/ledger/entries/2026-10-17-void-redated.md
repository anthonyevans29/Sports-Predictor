- **Built (#577), non-gate:**
  - One rule, `src/walters/redated.py`: "more than" `DESK_CLOCK_DRIFT` (1h), as the ruling words it (the Desk's own hold, addendum 83 item 2, is "at or more than"). A start with no clock is not compared.
  - A match is void when it has closing rows (`exports/closing_*.json`, never `host/`), none within the hour of its current `utc_date`, and its latest is re-dated. 50548: "void: re-dated 2026-10-17 00:00Z → 2026-10-18 21:00Z" until a closing row at 10-18 21:00Z exists. The closing rows are read by match id (`closing_starts`); the Python side never joined by teams or day.
  - Match id (addendum 109 item 2 (a)): the closing rows (the run's export rows) and the window card's rows (`export._fixture_row`) already carry `match_id` and `utc_date`; nothing on them changed. The Cockpit keeps each file row's `match_id` (`normalize`), every call stores it beside its kickoff (`baseCall`; null when the row had none), and the ledger JSON export, which is the stored ledger, carries both. Each result keeps its `match_id` (`outcomesFromDoc`).
  - Pairing (addendum 109 item 2 (b)): a call with a match id pairs with the result row of that id and no other; more than one such row is ambiguous and leaves it open, as the join did. A call whose id is in no loaded row stays open. Paired by id, a kickoff more than 1h from the result's date voids the call, whatever the gap (three days: void). A call without a match id is paired by the ±1-day team join as before and gets `legacy_join` (shown "legacy join": the ledger lists those calls, the void list marks them, the intake note and the P&L block count them). A re-log that reopens a call drops the flag with the label, except on a parlay leg the legacy join already graded (its ticket waiting), which nothing grades again.
  - A match id is machine-local (review of #577): the host and the laptop number matches apart (`deploy/hosting/compare_exports.py` masks it; `docs/specs/ncaa-shadow.md`: "match ids are machine-local and reusable; a mismatch is counted, never graded"), and the Cockpit claims calls from either machine's Desk files ("Load latest from host" auto-claims host rows with host ids). Pairing by the id alone graded a host-claimed NFL call on a laptop MLB row that carried the same number, and voided a call under a false re-dated label when a same-sport row of other teams carried it. The row of the call's id must now also name the call's home and away teams (`normTeam`); a row carrying the id for another game never grades or voids it. The call stays open with `id_mismatch`, listed in the ledger and counted in the intake note (`id mismatch N`), and a later pairing that verifies grades it and clears the flag. The sport is not compared on the id path: the files name it apart for one game (a soccer call, a PL fixtures row; a UNL call, an INTL results row), and a row of another sport naming both teams is that game.
  - Placeholder (addendum 109 item 2 Q2): the code's one definition, `src/ingestion/placeholder.py` `is_placeholder_kickoff` (04:00:00Z, midnight US Eastern), imported by `redated.py` and mirrored in the Cockpit (`isPlaceholderKickoff`, with a parity check in the Playwright script).
