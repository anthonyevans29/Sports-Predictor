- Readings made in this PR. Each is the conservative one (law 4), and each is for the architect:
  - **The results exports** are `<exports>/soccer_PL_results_*.json`, the file name `export-results --sport soccer --competition PL` writes. A file whose `competition_code` is not PL or whose `sport` is not soccer is named and not read. A file that is not JSON is counted as unreadable. The glob does not recurse, so `host/` is never read.
  - **Duplicates.** One row is kept per match_id, from the newest file: by the file's `exported_at`, then by its name. Every dropped copy is printed with both file names.
  - **Graded** means `graded.top_pick_hit` is true or false. Any other value is "ungraded", counted and left out.
  - **The pick and its model p.** The pick is `predicted.top_pick` (`home_win`, `draw` or `away_win`). Its model p is the side's own probability, `predicted.home_win_prob`, `draw_prob` or `away_win_prob`, else `predicted.top_pick_prob` (rounded to 4 places).
  - **The close** is the results row's `graded.close_fair`, read for the same side (HOME, DRAW or AWAY). This is the grading close of `close.graded_block`, which is the book close for a three-way board: `close_from_kalshi` derives no three-way price. A row whose `close_fair` is null, or has no fair for the pick's side, is "no close": named, with `close_stale_book` where the row carries it, and never in the cohort. A `close_reference` of `kalshi_only` or `kalshi` would not be the book close, so it is named and left out. A PL row should never carry one.
  - **The gap** is (model p − close fair) × 100, rounded to 9 places to remove float noise only. A row is in the cohort at gap ≥ `--min-gap-pp`, which defaults to 5 and is printed. Exactly +5.00pp is in and 4.99pp is out. The divergence stored in `graded.model_close_divergence` is not used: the ruling names the gap over the close.
  - **Stale stamps are counted.** `close_book_stamp_age_h` over `close.STALE_BOOK_H` (24) is printed as "stale", with `close_stale_unswitched` where present. The row is never dropped. The close stamp is `close_at`, and its ages are `close_minutes_before_start` (our capture) and `close_book_stamp_age_h` (the quote's own stamp). Whatever the row carries is printed.
  - **Re-dated rows are left out and counted with their label.** A row is void when it carries the export's `redated` label, or when the closing files on disk void it now (`redated.void_label` against the row's `date`). The receipt says which source voided it.
  - **The Desk's final call** uses `exec_cohorts.tally`'s selection, through its `_within` helper. It is the newest closing run's row within `desk_policy.DESK_CLOCK_DRIFT` of the results row's `date`. When no row is within the drift, the newest run's row is used, unless `void_label` voids it. A closing row is that game's only when its `home_team`/`away_team` are the results row's, because match ids are machine-local. Otherwise the receipt prints "no closing row (teams differ)". With no row at all it prints "no closing row". The call is `desk.call`, printed with `desk.pass_kind` on a PASS. A row with no desk block prints "no desk block on the closing row". `desk.pick` is printed only where it differs from the results pick.
  - **The prediction stamp** is the final closing row's `prediction.computed_at`, printed with `prediction.model_version`. Where there is no closing row it prints "not in the closing files". The results export carries no stamp.
  - **Injury inputs** are the final closing row's `input_quality.injuries.{home,away}.count`, the per-side block the guard reads. If that block is absent, `injuries.home_count`/`away_count` are used and labelled as such.
  - **The one-sided guard's state** is `desk_policy.one_sided_injuries` on the row as `desk_policy.normalize` reads it (sport soccer): it fires and names the empty side, or it does not fire. Beside it are the switch in code now (`INJURIES_ONE_SIDED_RULE`) and the Desk's own record at the run (`desk.pass_kind == "injuries_one_sided"`).
  - **The summary** gives graded PL rows, cohort size, cohort hits, and counts (with hits) by the Desk's final call, plus one JSON receipt line. It gives no verdict, no p-value and no threshold judgment.
  - **Read-only.** The script writes nothing and never imports `src.db.database`. A test runs it in a subprocess and checks both.
  - **Addendum 163 item 1, the table.** It is printed for the cohort and for the mirror set. The mirror is the graded rows with gap <= −`--min-gap-pp`, so −5pp by default. Exactly −5.00pp is in and −4.99pp is out, with the same 9-place rounding as the cohort line. Mirror rows need no closing row. They pass the same left-outs as the cohort: void, ungraded, no pick, no close, not the book close.
  - **Hit rate** is hits / n.
  - **The close-implied rate** is the mean of p, where p is each row's close fair for the picked side. Its 95% half-width in pp is 1.96 × sqrt(Σ p(1−p)) / n × 100: the sum of independent Bernoulli variances, as a share of n. The formula is printed on the line.
  - **The model mean** is the mean of the model's p for the picked side, the same p as the gap uses.
  - **The hypothetical return per unit at the close's fair price.** A hit returns 1/p − 1 and a miss −1, with p the close fair. The mean over the rows is printed. The interval is approximate: 1.96 × sd / sqrt(n) of the per-unit returns, sd being the sample standard deviation (n − 1). No interval is printed under 2 rows. The line says "before spread and fee". A row whose close fair is not inside (0, 1) is counted "unpriced" and left out of the return only. The mirror's return comes from the same function, so it is printed and labelled the same way; the ruling reads none for it.
  - **The cells** are the architect's cells from the 10-24 read, named constants beside `MIN_GAP_PP` and not knobs. `CELL_GAP_PP` = 12 covers members at gap >= +12pp, with the same rounding: exactly +12.00pp is in and 11.99pp is out. `CELL_PICK` = "draw" covers members whose `predicted.top_pick` is the draw. Each prints n and hits.
  - **The injury split, by the guard's state,** over the cohort's members, with n and hits per state:
    - "fires" and "does not fire" come from `one_sided_injuries`.
    - "no injury data / no closing row" means no closing row, or no `input_quality.injuries` block holding an integer count on both sides. The guard reads nothing there, so the row is not called "does not fire".
    - Any other state is printed by its own name ("rule off in code", "not evaluable").
  - **The injury split, by presence,** from the counts read (the per-side block, else `injuries.home_count`/`away_count`):
    - "both sides list someone": both counts above 0;
    - "one side lists none": exactly one count is 0;
    - "neither lists anyone": both are 0;
    - "unknown": no closing row, or a count missing.
  - **The pre-registration line** reads "next read pre-registered at n=60 (ARCHITECT 2026-10-24, addendum 163 item 1): same definition, read once", followed by the cohort's n now against 60 (`READ_AT_N`). No verdict is computed or printed, at n=60 or before it.
  - **The JSON receipt line** carries the table, the mirror table, the cells, the split and `read_at_n`.
