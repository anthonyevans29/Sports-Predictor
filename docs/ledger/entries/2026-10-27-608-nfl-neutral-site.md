- **Readings for the architect:**
  - **"Majority" is read strictly:** more than half of ALL the team's listed home games that season, preseason left out (v1's own filter). A game with no venue served counts in the denominator and never for a venue, so a team whose provider venue is served on only one or two of its home games reads UNKNOWN ("venue served on only k of n home games"), never the stadium of the one game served. A plurality (2 of 5) is UNKNOWN; a tie is UNKNOWN. The share, the listed count and the venue-served count are printed beside each home venue. A team with several international home games in one season, or thin venue coverage, can fall below half and read UNKNOWN. That is conservative (law 4), not "home".
  - **"The provider serves no venue" is a statement about what the provider serves:** it is made only on a run where every season asked was read. A FAILED read (expired key, quota errors, non-200), a capped season or a run with no rows is "venue NOT MEASURED" (`venue_served` null, exit 2), never the finding that stops the lane. A season read with no venue does not speak for a season that FAILED.
  - **The venue key is the served name:** normalized only by casefold and whitespace. The city is printed beside it, never used as the key. A naming-rights rename inside a season would read as "outside", so a game whose venue name differs but whose city matches the home venue's is flagged "SAME CITY ... (a naming variant? check)".
  - **Where the venue is read:** `game.venue` (else a top-level `venue`; a string is its own name). Both locations are law-1 hypotheses until the keys line prints a real response; nothing is read unless present.
  - **The join:**
    - first by `matches.external_ids["api_american_football"]` (the adapter's own key, service.py);
    - then by a re-keyed match's `api_american_football_prev`;
    - else by season + both teams (provider ids, then names) + kickoff date, labelled.
    - More than one candidate at any step (a provider id on two stored matches, a previous id on two, two matches on one key) is AMBIGUOUS and refused, never a guess, as the ingestion refuses (service.py).
  - **Walk vs stored can differ:** the walk folds in every earlier finished game. The stored probability is the predict-time read. Both are printed with the difference.
  - **`--db PATH`:** opens a file mode=ro (the #688 pattern) as an alternative to the app's database through `readonly_scope`. A missing file is refused (exit 2) before any provider call, and is never created.
  - **`--exports`:** optional. Without it, the void rule and the desk rows read "not read": the row's `void` is the label "not read (no --exports)", never null (null is "read, not void"), and its log-loss is marked "(void unread)".
  - **Malformed values:** a team id that is not a string or an integer is a malformed row (counted, never classified, #715 item 2). A venue name or city that is not a string is a malformed venue (UNKNOWN, counted).
