- **The finding (#794):** `reserve()` created `<eid>.started.json` with an exclusive create and then wrote it with `json.dump` into `os.fdopen`, with no cleanup. If serialisation, the write or the close failed (a full disk, a value that cannot be serialised), an empty or partial file stayed behind. `declared_unrun()` and `_reserved_why()` read that file as a spent run, so the one read was consumed with no game scored. No incident is known.
- **The fix:** the body is serialised before the exclusive create. After the create it is written whole, fsynced and closed, and the directory is fsynced. Any failure closes the fd, removes our own file and refuses (exit 2: nothing scored, the read is not spent). A failed removal refuses with INSPECT THE FILE. A KeyboardInterrupt is cleaned up and re-raised. Both declarations share the function (ncaa-elo-v1r, ncaa-elo-v2). The helpers mirror nfl_v2_gate's, so no cross-sport import is added.
- **Pinned unchanged:** the success bytes equal the pre-fix implementation's (a test runs the old function beside the new one); `ncaa-gate --preflight`'s console is byte-identical for both ids against origin/main 212398ea's module (golden captured from it). Nothing on the roadmap moves.
